# HostConfig 模块合同（L2）

模块职责: owns 三个 Agent Host 的调用面配置只读 adapter、通用宿主配置提交机制与 JSON key-path 写通道，以及 Claude Code/Codex 用户级写 adapter。Reader 结合 HostProfile 能力矩阵输出实时文件事实；通用 Writer 负责提交前漂移检测、原子替换与逐文件单槽备份/恢复；Claude adapter 集中映射四档；Codex adapter 集中映射三档并以行级最小修改保全 TOML/YAML 格式。does not own Pi 具体写入映射、Visibility Claim 持久化、文件监听、Skill Identity、UI 呈现或其他持久状态。

成员清单:
- `HostConfigReader.swift`：`HostConfigReader.invocationSurfaces(skillName:installations:)` 是唯一宿主事实读取入口；`ExposureLevel` 与宿主支持矩阵由 repo://Pagugu/HostProfile/HostProfile.swift owns。
- `HostConfigWriter.swift`：`rewriteConfiguration(at:transform:)` 与 `rewriteConfigurations(at:transform:)` 向 adapter 提供单文件/单动作多文件完整字节变换 seam；nil 或相同字节零写入。多文件动作先读取并产出全部变换，再一次重读全部文件防漂移；未漂移才把动作涉及的全部现存文件快照到各自 `<file>.pagugu-backup`，随后逐文件原子替换目标，使恢复槽属于同一动作。`merge(_:at:in:)` 复用单文件 seam 增删 JSON 叶子；`restoreBackup(for:)` / `restoreBackups(for:)` 逐文件原子覆盖现存单槽备份并保留备份；`claimState(expecting:at:in:)` 实时派生 JSON key 一致/分歧。
- `ClaudeConfigWriter.swift`：唯一 Claude Code 写 adapter。`apply(exposureLevel:forSkillNamed:)` 只写用户级 `~/.claude/settings.json` 的 `skillOverrides.<skill name>`；四档映射为 `on` / `name-only` / `user-invocable-only` / `off`，nil 删除 key；`claimState(expecting:forSkillNamed:)` 实时比较映射值；`restoreConfiguration()` 恢复同文件单槽备份。Project settings 仍只读。
- `CodexConfigWriter.swift`：唯一 Codex 写 adapter 与 TOML/YAML 窄行级 parser owner。`apply(exposureLevel:forSkillNamed:installations:)` 把全禁用映射为匹配 `[[skills.config]] enabled = false`、仅显式映射为用户级 `~/.codex/agents/openai.yaml` 的 `policy.allow_implicit_invocation: false`（该用户级事实影响全部 Codex Skill），完全暴露删除两处对应配置；匹配现存 `path` 或旧式 `name`，新增条目只写 Codex Installation 的 as-found `SKILL.md` 绝对路径；保留目标行之外的未知字段、注释、空白、换行与其他条目。两个用户文件同动作预检/快照，按保守顺序提交；写后经 Reader 重读完整事实，无法达到主张时明确失败。`restoreConfiguration()` 一次恢复同一最近动作的两个用户级文件快照。永不写 Installation 或 Skill Source 内的 `agents/openai.yaml`。
- Claude Code JSON 只读 schema：顶层 `skillOverrides` 对象，key 为 Skill name，value 只接受 `on` / `name-only` / `user-invocable-only` / `off`。项目 settings URL 只从 Project Installation 的 `.../.claude/skills/...` 路径派生；项目 key 覆盖用户 key，不存在时继承用户值；同一 Skill Identity 进入多个 Installation 上下文时取最严格档位，避免假报更宽暴露。
- Pi 独占 JSON 只读 schema：顶层 `skills` 对象，key 为 Skill name，value 为 `fullyExposed` / `nameOnly` / `explicitOnly` / `fullyDisabled`。不存在的文件或 key 表示 `fullyExposed`；`nameOnly` 与当前仍为 Unknown 的 `fullyDisabled` 如实返回 Unsupported。
- Codex 兼容 `[[skills.config]]` 的 `path` 与现存旧式 `name` 标识；`enabled = false` 优先派生 `fullyDisabled`。`policy.allow_implicit_invocation = false` 派生 `explicitOnly`。Reader 与 Writer 共用 `CodexLineConfiguration`，避免读取与写入对同一窄 schema 产生两套解释。

反模式: Reader 不写宿主配置；通用 Writer 不决定 key 所有权、具体宿主档位映射或 TOML/YAML schema，不静默重应用 Registry Claim；Claude adapter 不写 Project settings；Codex adapter 不整文件重排、不写 Skill 内容；不把缺失文件当读取错误；不把已存在但不可读/损坏文件默认为完全暴露；不把 Unsupported 静默映射为相邻档位；不把读取结果或分歧状态存入 Registry 或缓存为第二真相。

测试锚点: repo://PaguguTests/HostConfigReaderTests.swift（格式、默认值、能力缺口与 fail-closed）；repo://PaguguTests/HostConfigWriterTests.swift（通用提交、JSON 合并保全、单槽备份、恢复与实时分歧）；repo://PaguguTests/ClaudeConfigWriterTests.swift（Claude 四档）；repo://PaguguTests/CodexConfigWriterTests.swift（Codex 三档、TOML/YAML 保格式、备份、漂移与分歧）；repo://PaguguTests/AppModelSurfaceTests.swift、repo://PaguguTests/AppModelCodexTests.swift（AppModel 实时聚合与 Codex 动作）。
