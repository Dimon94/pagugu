## 回答的问题（#10 Question）

什么样的主窗口信息架构和交互能让目标用户在不理解软链接或 Git 分支细节的前提下，完成发现、理解关系、维护映射、手动检查、单个安全更新和阻断恢复的完整闭环？

## Verdict：Variant F「主从（目录 + 详情 + 原文）」

用户在 A/B/C（首轮三个）→ D（单列表极简）→ E（平铺按仓库）→ F（主从）的逐轮操作中做出并确认了以下裁决；A–E 全部淘汰。

### 信息架构（定稿）

1. **主窗口 = 主从结构**：左侧目录，右侧详情。
2. **目录条目 = 来源仓库（Skill Source）**，仓库行可收起/展开其子 Skill 行（默认展开，chevron 独立热区）；**无仓库可归的 Skill（来源不明的复制安装）以 Skill 本身为行**。
   - 依据（用户）：大部分 Skill 以套件（多 Skill 仓库）呈现，外部 Skill 亦然；单 Skill 仓库是特例但同构兼容；自有未建仓库的单 Skill 按 Skill 本身呈现。
   - 合同事实：身份/去重的 canonical 条目仍是 Skill（ADR-0001 §3 不动）；仓库行是呈现分组。更新单位是物理检出（ADR-0003 不动）。
3. **平铺目录，不预设分组标题**；排序在底层静默按行动优先级：**需要处理 → 可更新 → 尚未检查 → 无需更新**。用户明确否掉了过早暴露筛选决策的分组 bands。
4. **行状态 = 检出状态**，多检出在右侧详情逐条呈现，无聚合假状态；目录行短语如实并列组合状态（「1 个可更新 · 1 个需处理」）。排序按最严重态，动作按可行动。
5. **no-remote 归安静分组**（「仅本地 · 没有远程，不可更新」）：本地仓库未推送是常态开局，不是故障（ADR-0001 §2 同一哲学）。
6. **Skill 详情**：状态与检出（逐检出卡片：状态 + 上次观察时间 + 恢复方向 + 更新按钮）、安装位置（路径 + 宿主 + 投影/归因）、来源标识、**SKILL.md 原文（只读、可选中）**、相关记录。
7. **宿主 logo 槽位**：目录行与详情均显示 Claude / Codex logo，点亮 = 该平台已安装，灰显 = 未安装；前期只实现这两个 logo 接口（原型为手绘占位，真实资源归实现期）。
8. **次要对象的位置**：最近活动、扫描范围收进工具栏（带文字标签）；首次启动引导在右侧详情区（空 Registry 是正常态）；Registry 故障全窗口阻断接管（ADR-0008 §19）。

### 交互与呈现（定稿）

9. **全局只有一个检查动作**：工具栏「检查更新」→ 进度态「检查中 x/y」→ 逐项发布 → 结果进横幅与最近活动。
10. **更新爆炸半径诚实化**：更新按钮在仓库详情/检出卡片层；确认计划列出工作树、分支、HEAD→target SHA、落后数、影响范围，以及「同一仓库的 N 个 Skill 将一起前进」名单。双 Eligible 检出在确认页当次选择一个，不持久化。
11. **结果反馈的产品侧之家**：窗口顶部瞬时横幅（信息蓝 / 警示橙分级，可关闭）。成功、noop、取消后果、写失败、刷新失败、检查总结全部落这里。
12. **按钮与禁用**：动作按钮文案去 SHA 化（「更新…」「确认更新」）；禁用统一 tooltip 解释（受限恢复 / 部分扫描 / run 互斥）；sheet 必须有显式关闭；破坏性次要动作（删除失效映射、清空历史）降次要位置 + 确认对话框。
13. **映射流程**：映射 sheet = 可筛选、按来源分组的 Skill 列表；无已发现 Skill 时引导先添加 Project Scan Root；失效映射呈现原因、保留、可显式删除；来源移回自动复活。

### 被否决的方向（用户明确拒绝）

- B「行动工作台」：行动队列 + 表格 + 多板块 → 「乱」。
- C「来源地图」：来源树直接暴露多栏对象 → 「乱」。
- D「单列表（Skill 条目 + 分组 bands）」：条目粒度与更新单位不一致；分组标题过早暴露筛选决策。
- E「平铺按仓库 + DisclosureGroup 展开」：展开/导航嵌套一次点击触发多个响应；展开式不如主从直接。
- 弹窗固定高度留白、无关闭按钮、裸文本工具栏状态。

## 为 #11 输出的外部可观察验收场景

1. **首次启动**：空 Registry → 右侧详情区显示欢迎引导与「添加 Project Scan Root」；三个 Personal Skill Root 已自动发现并列出；添加后仅来源 Skill 出现在目录。
2. **发现与关系**：目录显示仓库条目（含子 Skill）与无仓库 Skill 行；宿主 logo 点亮/灰显与安装事实一致；同名异源按仓库天然区分。
3. **状态收敛**：12 个 Checkout Git State 在检出层逐条呈现，主状态 + 一句人工恢复方向；历史证据不覆盖当前状态。
4. **手动检查闭环**：检查更新 → 进度态 → 逐项发布 → 完成/部分完成横幅 + 审计记录；失败项回「尚未检查」并给原因；部分扫描结果时入口禁用并解释。
5. **安全更新成功**：更新… → 重查 → 确认计划（事实清单 + 精确 SHA + 同仓库 Skill 名单）→ 确认 → 成功横幅、状态变最新、审计开始+终态两段记录。
6. **noop**：重查时已最新 → 不弹确认，横幅告知。
7. **取消**：确认页取消 → 横幅说明后果（检出回「尚未检查」，重新检查恢复）+ 审计 cancelled 记录。
8. **失败恢复**：失败弹窗 = 失败类中文名 + 一句人工恢复方向；零自动重试/回滚；tip-changed 提示重新发起即可。
9. **来源映射**：来源不明行 → 指定来源（筛选分组列表）→ 成功后该行获得身份并移出无仓库行；失效映射原因 + 删除确认；来源移回自动复活。
10. **Registry 五语义**：空 Registry 正常；Scan Root 不可用为派生态（记录保留、可删除、恢复自动复活）；写失败 fail closed 横幅；损坏/未来版本受限恢复模式（quarantine 路径 + 重置为空 / 退出自行修复）；重置与清空审计均有显式确认与影响范围声明。
11. **审计呈现**：最近活动列表 / 单条详情（「当时记录」标注、reason 中文名 + 恢复方向）/ 清空确认；孤儿 Update start 显示「结果未知（已中断）」；无命令复制、无一键重试。
12. **MenuBarExtra**：只打开主窗口与退出，不承载工作流。
